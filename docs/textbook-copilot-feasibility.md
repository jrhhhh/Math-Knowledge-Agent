## 值得借鉴的能力

VeryMath 的阅读器使用 PDF.js，支持原页连续阅读、页码定位、目录、书签与文本选择。课程存储保留阅读位置、书签和课程对话。课程任务支持针对指定材料和阅读范围调用模型，生成讲解、习题及结构化资料。

对数学学习最有价值的部分是：用户不必离开教材，也不用每次重新描述教材名称、页码和讨论对象。提问、追问、引用和学习成果围绕当前阅读对象持续进行。

其前端为 React/TypeScript/Vite，服务端为 Node，当前 Agent 使用内嵌 pi runtime。当前源码还存在全局 activeRun 限制，因此直接复用整套运行时并不天然满足多人并发。课程材料本地存储，也不代表调用远端模型时材料不会发送给供应商。

## 接入方式比较

| 方案 | 优点 | 成本和限制 | 判断 |
| --- | --- | --- | --- |
| 链接到独立 VeryMath 服务 | 较快试用现成伴读 | 两套数据、会话、模型配置；成果需桥接 | 可用于体验验证 |
| iframe 嵌入整套 VeryMath | 表面入口统一 | 仍是两个产品；跨源交互、响应式、路由和状态同步复杂 | 不宜作为长期主方案 |
| 在现有教材模块上实现伴读 | 沿用现有学习数据和验证边界 | 需要实现阅读器和上下文协议 | 推荐 |
| 全面迁移到 VeryMath 架构 | 可大量复用其前端 | 迁移现有 FastAPI/API/数据库/学习闭环成本高 | 当前投入缺乏必要性 |

借用代码时应核对固定版本的 Apache-2.0 许可，保留适用的版权与许可声明、标明修改，并检查所使用依赖的许可。无需为阅读功能迁移整个前端；PDF.js 可作为独立前端模块接入。

## 第一版的产品范围

桌面：左侧教材原页与可收起目录，右侧伴读对话，支持拖动调整栏宽。手机：阅读/对话切换，保留页码与引用，避免挤成两条窄列。

操作范围明确区分选段、当前页和指定页范围。每条提问显示教材名称和 PDF 页码；翻页不悄悄改变已发送问题的范围。提供“解释这一段”“补全推理”“举例/反例”“只给提示”四类快捷动作，也允许自由提问。

回答区分教材原文、补充解释和自构例子，引用可跳回原页。找不到支持材料时明确说明；未校对 OCR 文本仍可用于辅助讨论，但必须带来源状态，不能自动升格为已审核知识。

阅读位置、书签与教材对话持久化；讲解可保存到既有笔记；从阅读中生成的练习保留来源并以草稿进入审核流程。

第一版不把自动课件、视频、整书图谱或任意 shell Agent 执行纳入核心范围。这些可以在伴读体验稳定后分别评估。

## 建议的数据与接口设计

新增阅读上下文对象：document_id、PDF 页范围、chunk_ids、选段文本、内容版本/摘要、范围模式。由服务端检查教材和片段归属、范围上限，装配真实内容，避免只依赖客户端传入文本。

新增持久化阅读状态：教材 ID、页码、缩放、书签、当前课程会话；会话关联教材，消息记录本轮范围快照。阅读状态与掌握状态分开，翻过页不计为学会。

教材伴读端点可以复用已有问答生成、流式事件、取消及错误处理，在调用前增加范围解析；旧问答端点默认行为保持兼容。来源点击通过阅读器定位事件返回原页，笔记关联同一引用快照。

涉及上传文件与数据库的备份时，应覆盖 PDF 原文件和新增阅读数据；仅备份 SQLite 不构成完整教材备份。

## 主要难点

1. 原生 PDF iframe 无法稳定提供统一的选段与页码事件。PDF.js 替换是伴读体验的关键工程工作，需检查 worker 配置、跨源文件读取及移动端表现。
2. pypdf 文本层提取不是数学 OCR。分式、上下标、矩阵和跨栏阅读顺序需与原页核对；扫描页需要额外识别能力与成本评估。
3. “解释这一章”需要范围受控的检索与分段读取，不能每轮把整书送入模型。限制默认范围、缓存提取结果、展示超范围提示，并测量实际响应时间与调用成本。
4. 当前 KnowledgeChunk 通常一页一段，章节字段较粗。目录、定理/例题边界、前置章节检索需要额外结构索引；跨页证明不能被错误拆成独立结论。
5. PDF 页序与教材印刷页码可能不同，需分别显示并提供校准。引用保留内容版本，避免校对后历史回答无法追溯。
6. Math-Agent 为本地个人产品。若改成多人部署，需要用户隔离、文件授权及任务并发控制，不能直接使用全局课程状态。

## 分阶段推进及验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| A 范围验证 | 一个真实教材章节，PDF.js 原页与选段 | 文字层选择、跨页内容、目录定位、扫描页降级 |
| B 伴读最小版本 | 双栏、范围上下文、流式追问、引用回跳、阅读状态 | 刷新恢复、翻页不串问题、切书不串对话、取消可恢复 |
| C 学习闭环 | 笔记来源、章节练习草稿、复习入口 | 引用版本可追溯，生成内容不自动变为已审核 |
| D 内容增强 | OCR、章节结构、前置知识、更多资料 | 公式识别误差、处理成本、教学质量评测 |

工程量初判：双栏与阅读状态为中等；范围约束和证据回跳为中等；高质量数学 OCR 与自动章节理解为高。具体排期应在阶段 A 验证后估算，本次未给出已测得的工期或百分比。

建议首个样本使用用户已有的《最优化导论》某个完整小节，包含定义、公式和推导；再增加一个跨页证明和一个扫描页样本。内容必须按实际原页核对，不凭页号猜正文。

通过标准包括：同一问题可在不离开教材时完成追问；引用能返回正确 PDF 页；刷新恢复阅读位置；课程对话不串书；模型找不到依据时不编造来源；手机无横向溢出；已存在的笔记、练习和教材校对功能不回归。

## 产品判断

优先级高。该功能能把已有教材导入从资料维护入口变成日常学习入口，并连接问答、笔记和练习。价值判断应通过真实章节使用验证：用户是否减少复制粘贴和切换页面，能否更快解决教材中的具体卡点，是否愿意继续阅读下一节。
